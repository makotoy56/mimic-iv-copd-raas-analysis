# ICU-COPD 年齢・追跡時間の修正と再検証

実施日：2026-11-18（日本時間）。修正前 HEAD：`56ab7db0a424e5b6b63e04651d616c4adb1270e1`。

## 修正内容

- `04_build_outcomes.sql`：`DATETIME_DIFF(endpoint, intime, MICROSECOND) / 86400000000.0` に統一。死亡・生存退院双方の元時刻の逆転、真のゼロ、欠損、イベント値をテーブル置換前に検査する。死亡時刻欠損時の退院時刻代用とフラグは保持する。
- `01_extract_base.sql`：`anchor_age + EXTRACT(YEAR FROM admittime) - anchor_year` を入院時の近似年齢として成人選別に使用する。
- `02_build_cohort_copd.sql`、`03_build_baseline.sql`、04 と extended：同じ年齢を引き継ぎ、元の `anchor_age` と `age_anchor_topcoded` を保持する。03 は年齢をリセットしない。
- `anchor_age=91` は基準年で89歳超の集約群であり、補正後も正確な年齢は復元できない。通常の年齢も年単位の近似である。主モデルの年齢項は既存の連続値仕様を維持し、集約群除外を追加の感度分析とした。

## 検証方法

修正済みの実 SQL から SELECT 部分を取り出し、成人選別前からソースを再構成した。年齢・時間の二つの変更を分離する4条件で、04a refined、04b、04c の4仕様を推定した。別途、集約年齢群を除く corrected 04a を推定し、合計25モデルを比較した。各モデルの係数、95% CI、p 値と rank 変換による共変量別 Schoenfeld PH 検定は [集計 JSON](AGE_TIME_REVALIDATION.json) に保存した。元データの個票・識別子・個別日時は保存していない。

実 SQL と実 QA 条件を使う12の合成ケース（時間境界をまたぐ2分、同じ時間内の10分、1マイクロ秒、死亡時刻代用、真のゼロ、両種の逆転、欠損、イベント欠損、18歳境界の両方向、高齢者集約群）が通過した。7つの QA 条件も想定どおりに動作した。合成試験の元データ読み取り量は0バイト。

## 年齢・イベント件数

全条件で11,964入院、1,692死亡。成人境界をまたぐ入院は両方向とも0件。5,471入院（45.7%）で年齢が変わり、平均年齢は69.1615歳から71.3053歳へ変化した。集約年齢群は438入院。

時間修正後、追跡ゼロは1件から0件になり、正の1時間未満の死亡2件が保持された。死亡時刻代用は2件。真のゼロ、逆転時刻、追跡時間欠損は今回の実集団にない。

KM の年齢補正のみの結果は修正前と同じだった。今回、適格集団が変わらず、KM が年齢を調整しないためである。生存退院は従来どおり打ち切りとしており、これらは競合リスクを考慮した院内死亡確率ではない。

両方修正後の04a refined の PH p 値は年齢0.7980、性別0.3250、RAAS0.7206。04b も全共変量でp>0.05だった。一方、04c core は CHF（p=0.00000575）と SOFA（p=0.01924）で PH 仮定からの逸脱が示唆された。ICU 拡張モデルにも CHF・SOFA・一部 ICU カテゴリで同様の課題が残る。PH 仮定が全モデルで解決したとは解釈できない。

ICU拡張モデルでは `icu_type_Medicine` の低分散警告が修正前後ともに記録された。今回の修正によって新たに生じた警告ではないが、係数の安定性に関する既存の制約である。層別・患者クラスタリング・frailty・競合リスクなど、他のモデル仕様は変更していない。
